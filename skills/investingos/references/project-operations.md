# Project operations

Use the root `README.md` as the current source for installation, supported Python versions, examples, test status, third-party credits and license notices. Consult `--help` for exact command arguments and `references/source-management.md` for source imports, storage, Markdown provenance and viewer details. Do not claim a platform, integration or version has been tested unless the README or an actual check confirms it.

For optional Markdown authoring scaffolds, consult `../templates/README.md`. Reuse canonical UUIDs, create one note per entity and link to related notes rather than duplicating their content. Templates do not synchronize Markdown edits into the JSON project.

## Installation and clients

- Run `scripts/install.py` with a supported Python interpreter. Its default activates the main skill in the shared discovery path; opt into other clients or skills only as requested. The installer checks the manifest and does not replace existing files or remove earlier links. Restart the chosen client and independently verify discovery. Windows needs suitable symbolic-link permissions. Client paths are adapters, not engine dependencies.
- For another skill or collection, follow `docs/skills-management.md`: inspect and pin the source, check licenses, select requested skills, preserve attribution, configure only requested clients, and update the index and credits. Consult `docs/ai-clients.md`, `skills/INDEX.md` and `docs/research-tools.md` as needed. Optional integrations and third-party dependencies are not automatically installed. Review unresolved third-party provenance and licenses before redistribution.

## Create, structure and inspect

- Use `create` to initialize a project and `show` to inspect it. For a simple UTF-8 topic list, `create --outline` makes one node per nonempty line and does not interpret indentation. For an indented hierarchy added to an existing project, `import-outline` expects two spaces per level and rejects duplicate titles and skipped levels. Preserve the input.
- Store learner goal, audience, prior knowledge, scope, desired depth, constraints and language with `create` options or `set-profile`. `set-note` stores flexible Markdown on a node; use `--input-file` for longer notes. The local viewer displays profiles and notes but editing those records still uses the CLI.
- Create concepts with `add-node`, views with `add-view`, and relationships with `add-edge`; use returned stable IDs. `contains` points parent to child, `part_of` child to parent, and `requires` topic to prerequisite. Reuse nodes across views. Expand only the requested branch and avoid concurrent project writers.
- Maintain a hierarchy with `rename-node`, `move-node FILE NODE VIEW [--parent PARENT] [--position N]` and `remove-edge FILE EDGE`. Moves retain the knowledge-node ID, change only the selected hierarchy view and reject cycles or ambiguous multi-parent moves. Positions are one-based; root ordering and sibling order are stored separately from concept identity. `remove-edge` detaches a relationship and never deletes either node.
- Choose a view pattern to match the task: a recursive study outline; multiple hierarchy views for alternative classifications; a concept network for cross-topic relations; or prerequisites and an ordered competency pathway for learning sequence. A hierarchy view is not a competence scale. Chronologies and processes can be represented with dated/staged nodes and supported hierarchy or network edges, but there is no dedicated timeline type or custom edge type. The hierarchy has no fixed depth limit.
- Before expanding, inspect the target view, parent and sibling titles. Reuse existing node IDs across views, add only missing concepts, and assign containment edges to the intended hierarchy view. Audit after structural changes. Superindex positions can change as siblings are added or reordered; UUIDs remain stable. Do not duplicate nodes to create alternative views or move concepts between views without checking existing links.
- Run `audit` to check integrity, duplicate titles and IDs, and cycles; it cannot identify every semantic duplicate or verify claims. `suggest-duplicates` proposes title matches; inspect them before any explicit `merge-nodes`. A merge preserves removed metadata and ID in the retained node, but the removed ID is not a lookup alias.

## Research and competencies

- Register sources and claims with `add-source` and `add-claim`; link relevant nodes and source IDs. Claims default to `unverified`; `supported`, `disputed`, and `outdated` are user assessments. Supported claims require a source but this is not automatic verification.
- `import-folder PROJECT INPUT_DIR OUTPUT_DIR` batch-imports supported local document formats, preserves input subfolders, skips matching source hashes and reports per-file failures. `set-source-status` marks a source `inbox`, `processed` or `archived`; these are library workflow states and have no bearing on truth or verification.
- `index-documents PROJECT` builds or incrementally refreshes a local SQLite FTS5 index from extracted text; `--rebuild` recreates it. The hidden index file is adjacent to the project and git-ignored. Use `search-documents PROJECT QUERY` after indexing. `search --documents` remains a direct scan. Indexes contain private extracted text, and missing or removed files are pruned on refresh.
- `draft-note PROJECT NODE OUTPUT.md` creates a non-destructive study-note scaffold with the project's identity and source-linked claims. Read the actual source materials before drafting a synthesis; fill the scaffold and save it to the project with `set-note`.
- `add-research-task` and `set-task-status` track investigations. `add-evidence` records a locator for a source already linked to a claim; `review-source` records a manual review date, and `schedule-review` tracks a future review. None automatically verifies claims or establishes freshness. Use `research-report` to inspect recorded gaps and contradiction edges, not to claim automatic contradiction discovery.
- `search-crossref`, `search-pubmed` and `search-source` (59 open sources, no key) retrieve online scholarly metadata leads when network access is available and authorized; verify the sources. PubMed results include preprints and reviews, so read `publication_types`. `NCBI_API_KEY` is optional and must stay out of project files; see `docs/research-tools.md`. `lookup-ora` fetches one Oxford Research Archive record by UUID or URL; it cannot search. `lookup-preprint` fetches a bioRxiv or medRxiv preprint by DOI and `worldbank-data` returns statistics, not studies. Results carry a `kind`; do not treat a preprint, registry record or statistic as a peer-reviewed article. Advice about a person's own situation (health, mental health, law, money, safety or any other field) belongs to the qualified professional for it, whether or not that kind of professional is named in the docs; this tool does not replace one. The research-tools guide lists the publisher sites that are deliberately not supported. `export-csl` and `export-bibtex` output recorded bibliographic fields without inventing missing information.
- Use `add-competency` to describe a capability, node, configurable level and expected evidence; use `add-learning-path` for an ordered competency sequence. These levels are not official qualifications and are separate from thematic depth. Personalized lessons, progress tracking and financial analysis are not implemented.

## Local viewer and export

- `web PROJECT` starts a local-only viewer; use `--port` as needed and stop it with Ctrl+C. The viewer displays topics, relationships, indexes, sources, claims, evidence, competencies, paths and tasks. Editing outside import uses the CLI; refresh after changes. Its search filters the selected section and does not search document bodies.
- The superindex numbers the `contains` and `part_of` relationships assigned to each view; it can show the same concept in several branches. Numbers reflect positions and may change; node IDs remain stable. Views without hierarchical relationships have no indexed topics.
- For maintainable study material, keep node titles concise and descriptions focused, and expand a branch in small increments. Use the view-specific index for navigation, network edges for cross-links, and `requires` or competency paths for learning order. Do not represent these different relationships as one deep tree.
- For the selected page, Word export provides an approximate preview and editable DOCX. PDF uses browser print/save, with final pagination controlled by the browser. Neither provides a full-project export or verified pixel-identical rendering. See the source management reference for import form storage and source sections.
- `export` writes an Obsidian-compatible Markdown snapshot to a new directory: a numbered nested index per hierarchy, one note per knowledge node, one note per source, and a `sources.md` library grouped by media type, falling back to publication type. Related concepts and sources use stable-ID Obsidian links. `update-export` only updates eligible unchanged managed notes; it reports conflicts, preserves user edits and deletions, and does not remove notes for removed nodes. Older snapshots lacking a manifest cannot be updated. Edits in Obsidian do not sync back to project JSON. Back up the vault and avoid concurrent edits.

## History, backup and diagnostics

- Project overwrites retain a previous JSON snapshot in `.InvestingOS-history/<project-id>/` beside the project. History can contain private data, grows with edits and is not automatically pruned. `compare` compares snapshots from the same project; `restore` writes a selected snapshot to a new destination.
- `doctor` reports available Python and optional executables; it does not verify their versions or connectivity. `backup` and `restore` cover project JSON only and refuse existing destinations.
- `migrate` upgrades older project JSON through the explicit migration chain and stores the pre-migration file in history. Writes use a local exclusive lock and reject stale project snapshots loaded before another writer saved; a leftover lock after a crash must be inspected and removed manually.
- `backup-bundle` includes the project plus only explicitly selected files or folders; it refuses symlinks and existing destinations. `restore-bundle` validates and restores to a new directory. Archives are unencrypted and do not preserve empty directories. Stored paths continue pointing at original locations; `rebase-paths` requires existing targets, checks available hashes and uses the current OS path format.
- Keep personal data and credentials outside the public repository, inspect what a backup includes, and never publish or delete user files without authorization. Use the README's development and test instructions for verification, reporting skipped checks and actual interpreter versions.
